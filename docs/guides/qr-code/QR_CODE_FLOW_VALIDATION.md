#### `timesheet_entries`

```sql
CREATE TABLE timesheet_entries (
  id UUID PRIMARY KEY,
  teacher_id UUID REFERENCES users(id),
  student_id UUID REFERENCES students(id),
  parent_id UUID REFERENCES users(id),
  qr_code_id UUID REFERENCES parent_qr_codes(id),
  check_in_time TIMESTAMP WITH TIME ZONE NOT NULL,
  check_out_time TIMESTAMP WITH TIME ZONE,
  duration_minutes INTEGER,
  location JSONB DEFAULT '{}',
  notes TEXT,
  status VARCHAR(20) CHECK (status IN ('checked_in', 'checked_out')),
  created_at TIMESTAMP WITH TIME ZONE,
  updated_at TIMESTAMP WITH TIME ZONE
);
```

**Purpose**: Records all teacher check-ins and check-outs with timestamps for billing.

**Automatic Features**:

- Duration auto-calculated on check-out (via trigger)
- Updated_at auto-updated on changes (via trigger)
- Constraint: check_out_time must be after check_in_time
- Constraint: duration_minutes must be positive

### Duration Calculation

**Method**: Database Trigger (`calculate_timesheet_duration()`)

```sql
NEW.duration_minutes := EXTRACT(EPOCH FROM (NEW.check_out_time - NEW.check_in_time)) / 60;
```

**Example**:

- Check-in: 2:30 PM
- Check-out: 4:00 PM
- Duration: 90 minutes (1.5 hours)

## Security & Validation

### QR Code Security

1. **Signature Validation**
   - Each QR code contains encrypted signature
   - Signature = `base64(parentId-studentId-secret)[0:16]`
   - Server validates signature on every scan
   - Prevents QR code tampering

2. **Expiration**
   - QR code data includes timestamp
   - Codes expire after 24 hours
   - Database records also have `expires_at` (30 days)

3. **Student Specificity**
   - QR codes are tied to specific student
   - Cannot be reused for different students
   - Validates student assignment to teacher

**Code Reference**: `timesheet.service.ts:430-434`

---

### Business Logic Validation

1. **Duplicate Check-In Prevention**
   - System checks for active check-in before allowing new check-in
   - Error: "Teacher is already checked in for this student"

2. **Check-Out Requirements**
   - Requires active check-in before allowing check-out
   - Error: "No active check-in found"

3. **Timestamp Constraints**
   - Check-out time must be after check-in time
   - Duration must be positive
   - Database constraints enforce these rules

**Code Reference**: `timesheet.service.ts:166-176`, `002_timesheet_tables.sql:45-50`

## Row Level Security (RLS)

### Parent QR Codes

- **Parents**: Can view, insert, and update their own QR codes
- **Teachers**: Can view QR codes for students assigned to them
- **Enforcement**: `parent_id = auth.uid()` or teacher assignment check

### Timesheet Entries

- **Teachers**: Can view, insert, and update their own entries
- **Parents**: Can view entries for their students (read-only)
- **Admins**: Can view all entries
- **Enforcement**: `teacher_id = auth.uid()` or `parent_id = auth.uid()`
